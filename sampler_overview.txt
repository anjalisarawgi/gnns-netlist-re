GNN Sampling Methods – Overview and Recommendations for AES Netlist
Classification

This document summarizes the sampling strategies available for training
GNNs on large hardware netlists. It explains how each sampler behaves,
why sampling bias exists, and which approaches best suit
subcircuit/boundary detection in AES graphs.

1.  Why Sampling Matters in Large Graph Training Training GNNs on large
    graphs requires sampling because full-batch training is too
    expensive. Sampling determines:

-   which nodes the model sees per epoch
-   how often each subcircuit is visited
-   whether rare or isolated subcircuits (e.g., S-boxes, key schedule
    logic) receive enough gradient updates
-   whether the training set is balanced or biased

Understanding sampler behavior prevents overfitting to dense regions and
ensures fair learning across the graph.

2.  Categories of Samplers 2.1 Neighborhood Samplers

-   NeighborLoader (GraphSAGE sampler)
-   Layer-wise samplers (FastGCN, LADIES)

2.2 Subgraph Samplers - Cluster-GCN (partition-based) - GraphSAINT (Node
/ Edge / Random Walk samplers)

2.3 Random Walk Samplers - Node2Vec-biased walks - PPR-based selections

2.4 K-hop EGO Samplers Extract k-hop neighborhoods around random nodes.

3.  Which Sampler Fits AES Netlist Classification Best? Recommended:

-   Cluster-GCN → subcircuits are naturally clustered
-   NeighborLoader → stable, local, and easy
-   GraphSAINT Node Sampler → more uniform than random-walk

Random-walk tends to oversample high-degree AES cores.

4.  Key Diagnostics to Understand a Sampler Only apply to the training
    graph:

-   per-epoch coverage
-   cumulative coverage
-   sampling frequency histogram
-   class-conditioned frequency
-   degree vs frequency correlation
-   PageRank vs frequency correlation
-   long-tail distribution metrics (Gini, entropy)

These help detect oversampling of dense modules and undersampling of
rare subcircuits.

5.  Test Graph No sampling diagnostics apply to the test graph. Only
    evaluate the model:

-   accuracy
-   precision/recall/F1
-   predicted probability distributions

6.  Simplifying Complexity To avoid confusion:

-   freeze the model → use simple GCN temporarily
-   freeze the graph → train on one GML file
-   study only the sampler until understood
-   reintroduce complexity later (GAT, weighted loss, merging graphs)

This reduces moving parts and improves interpretability.
